# 016：domain skill 散佈 — 從只裝一個工具目錄，到單一源 + 枚舉投影

> 2026-06-12（2026-08-14 補一次根因修正）。一條散佈機制的決策轉移。起點是問「knowie 學出來的 skill 跨不跨廠商」。

## 轉移
- **舊（superseded）**：學來的 domain skill 只裝進 `.claude/skills`，綁死單一工具。底下還壓著一個錯誤認知：**「Codex 沒有 skill 機制，所以跨廠商做不到」**。
- **新（current）**：`knowledge/skills/` 是**唯一真相源**（committed），per-skill **相對** symlink 投影到 `.knowie.json` → `skillDirs` **枚舉出的每一個**目錄（投影本身 gitignore）。投影由 **AI 內部執行**——consolidate 固化時順手做、judge §5 維護時 re-ensure／heal——**不是 CLI**。

## 為什麼變
1. **舊認知是錯的。** SKILL.md／agentskills.io 在 2026 已是跨工具開放標準（Claude Code／Codex／Gemini／Copilot／Cursor／Cline／Windsurf／OpenCode 都讀），`.agents/skills/` 是新興的中央源慣例。「skill 跨廠商」在**格式層早就解決**，knowie 缺的只是散佈的最後一哩。
2. **投影可逆**（symlink + gitignore）→ 依延伸原則 5「可逆的自動化」由 AI 直接做，不需人確認。人要確認的是上游那步：這個 skill 該不該固化。
3. **CLI 只管「AI 不在場」的自舉**（從 npm 裝 knowie 自己的 package skill）。domain skill 投影是「AI 在場之後」的事。
4. **不自造引擎**——只接 agentskills.io 標準 + `.agents/skills/` 慣例（[協議非平台](../concepts/協議非平台.md)）。

## 被否決的選項
- **`knowie sync` CLI**：把在場該做的塞回 CLI。見 experience「在場的 AI 自己做，CLI 只給『AI 不在場』的自舉」。
- **整個目錄 symlink**（而非 per-skill）：會蓋掉 npm 裝進去的 package skill——兩類 skill 必須並存。

## 後續修正（2026-08-14，五專案審計）
機制建了，但**每個真實庫的 `.agents/skills/` 都是空的**。根因不是措辭，是**沒有枚舉來源**：投影由 AI 做，而目錄清單當時只活在 `registry.js`（CLI 的資料），skill markdown 讀不到——所以 AI 只投影它自己讀的那個目錄。修法：`init`/`update` 把解析後的清單寫進 `.knowie.json` → `skillDirs`，capture／judge 改成枚舉它。同時修掉「symlink 寫成絕對路徑、換 checkout 就全斷」。現場見 [episode](../episodes/2026-08-14-五專案外推審計.md)。
