# judge 再機械一階——措辭擋不住的，改成 grep 得到的

> 2026-08-14 五專案外推審計。draft，design 型。
> 怎麼冒出來的：0.7.2 才剛用措辭收緊「完成不是轉移」「vision 出列要收斂」。掃五個真實專案時發現，**病灶還在，而且每一個都能用一行 grep 抓到**。
>
> **已提升（2026-08-14）**：→ [vision 路線圖「judge 再機械一階」](../vision.md)。本檔為在建設計脈絡，留到該項完成才兌現出列。

## 前提：這是既有教訓的第二次適用

[experience](../experience.md)「有些 bug 是執行層的，協議層（skill 措辭）解不了」當初是為 migrate 寫的。這次的證據說**同一條對 judge 也成立**：0.7.2 的收緊是措辭，而下面五條病灶在措辭之後仍然存在於真實專案裡。

差別在於 migrate 那次的解法是「換執行層（遮罩 harness）」，這次不必——**judge 已經有執行層了**（§3 的 grep/ls 機械掃描）。缺的只是把這幾條從「判斷題」下放成「掃描題」。

## 五條可機械化的檢查

### 1. history 檔名的形狀＝轉移詞

KnowField 的 91 筆 history：`008-拉模式完成`、`013-Web-介面完成`、`020-promote-RAG-MVP`。打開 008：

```markdown
## 轉移
- 舊：只有推（每日分診）；拉模式僅為 draft 設計。
- 新：**拉模式（主題拉取深挖）實作完成**（spec 002）。
```

**「還沒做」被寫成「舊」**——那不是轉移，是進度條。

對照組：wewayfinders 41/41 全是 `X 從 A 到 B`（`002-技術路線從託管PaaS到自租VPS`、`013-佔位檔案從否決到暫時是系統知道的事實`），semorphe 幾乎全是。**檔名本身就是 diff**，不打開就知道那條轉移是什麼。

- **掃描**：`history/` 檔名不含轉移詞（從…到／改為／否決／推翻／擴充為／降為）→ 標黃。
- **掃描**：`## 轉移` 的「舊」欄位以「尚未／只有／僅為 draft／無」開頭 → 標紅（那是「還沒做」不是「舊決策」）。
- 為什麼檔名夠用：它是**最便宜的形狀檢查**，而且寫檔名的當下就會被逼著想「這到底是哪一條決策變了」。

### 2. vision 的 `[x]:[ ]` 比

| 專案 | [x] | [ ] | 比 |
|---|---|---|---|
| KnowField | 225 | 6 | **37:1** |
| ArduinoCAD | 44 | 3 | 15:1 |
| VizGPT | 159 | 81 | 2:1 |
| wewayfinders | 8 | 10 | 0.8:1 |
| semorphe | 13 | 21 | **0.6:1** |

judge §5 的測試是「這行說的是*往哪去*，還是*我們完成了什麼*？」——正確但沒有可量的版本。這個比值就是它的機械代理：**vision 是朝前看的文件，已完成項比例超過 ~3:1 就代表出列機制沒在跑**。

KnowField 的 37:1 和它的 91 個 changelog history 是同一個病的兩面：**整個 knowledge/ 退化成進度追蹤器**。

### 3. 整層孤兒要升級成一個 🔴，不是 N 個 🟡

實測連結健康：

| 專案 | 連結數 | 死連結 | 孤兒 |
|---|---|---|---|
| VizGPT | 1490 | 0 | 1 |
| semorphe | 720 | 0 | 0 |
| wewayfinders | 563 | 0 | 0 |
| ArduinoCAD | 358 | 5 | 3 |
| KnowField | **14** | 0 | **116**（history 91/91、draft 21/26、episodes 4/5） |

KnowField 全庫只有 14 條連結，**91 筆 history 全是孤兒**——沒有任何檔案指向它們，所以 next/judge 永遠讀不到。寫進去等於寫進 `/dev/null`。

judge §3 現在逐檔報孤兒。91 個 🟡 會被當噪音滑過去；那不是 91 個孤兒，是**這一層從來沒被接上過**。

- **掃描**：某層孤兒率 > 80% → 升級為結構性 🔴，訊息是「這一層沒有接進 Key Extensions，等於不存在」。

### 4. 教訓缺「來源」

semorphe 46/109、wewayfinders 19/73 有來源（數據與成因見 [知識條目的形狀](2026-08-14-知識條目的形狀.md)）。這違反 [根本原則二](../principles.md)。

judge §2 現在只說「experience — lessons distilled (four-part), not raw events?」——判斷題。

- **掃描**：`### ` 標題後到下一個 `### ` 之間沒有來源指標（`來源`／指向 `history/`、`episodes/`、commit hash 的連結）→ 標黃。

### 5. 檔名禁空白 + symlink 必須相對

ArduinoCAD 的 5 條死連結成因單一：`episodes/001-電路圖算繪 SOTA 調查.md` 檔名帶空白，連結一邊寫 `%20` 一邊沒編碼。五個專案只有它的檔名有空白。

VizGPT 的 skill symlink 是絕對路徑（`/Users/timcsy/Documents/Projects/VizGPT/...`），其他四個是相對路徑 `../../knowledge/skills/...`。絕對路徑換機器、換 checkout 位置、別人 clone 下來就全斷。

- **subdir README 補一句**：檔名用 `-` 不用空白。
- **judge §5 re-ensure 補一句**：投影一律相對路徑，掃到絕對路徑就修回來（可逆 → 直接做，不問）。

## 一條紀律，五個實例

這五條的共同形狀：**judge 目前把它們當「讀了之後判斷」，而它們全都是「掃一次就知道」**。

而分工的理由 [experience](../experience.md) 早就寫了——「寫的人對自己寫的有『可見性錯覺』（靠機械掃描補，不靠記性）」。0.7.2 用措辭補了一輪之後仍然漏，是因為**措辭是寫給「會讀它的人」的，而可見性錯覺的定義就是那個人覺得自己已經做到了**。

同時要守住既有邊界：這五條全部只掃 `knowledge/` 內部，不越界去掃 docs-vs-code（[experience](../experience.md)「why-lane 不掃 what-consistency」）。它們檢查的是**知識條目自己的形狀**，不是知識與 code 的一致性。

## 出口

design 型 → 成熟後進 vision roadmap，驗收就是這五條各自的 grep 能在五個專案上跑出預期結果（現成的測試集：KnowField 應該全紅、semorphe/wewayfinders 應該全綠）。

**這批有一個罕見的優勢：驗收資料已經存在**。不必等未來的使用產生證據——五個真實專案就是 fixture。
