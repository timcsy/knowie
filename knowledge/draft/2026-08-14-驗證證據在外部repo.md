# 驗證證據住在別的 repo——knowie 結構上看不到自己的兌現

> 2026-08-14 五專案外推審計。draft，problem + design 型。
> 怎麼冒出來的：使用者請我看五個真實專案（ArduinoCAD / VizGPT / KnowField / semorphe / wewayfinders）用 knowie 的效果。掃 `knowledge/skills/` 時發現一件事——vision 上還掛著未完成的驗證項，實際上五個專案全部兌現了。
>
> **已提升（2026-08-14）**：→ [vision 路線圖「驗證證據回收（外部 repo）」](../vision.md)。本檔為在建設計脈絡，留到該項完成才兌現出列。

## 撞到的事實

`vision.md` 的「程序記憶自習得」區塊至今寫著：

```
- [ ] 在一個真實專案長出至少一個 domain skill（驗證類，merge 後）
- [ ] symlink/Windows + 真實 Codex/Gemini 讀到並用到 domain skill（驗證類，merge 後）
```

實測（2026-08-14）：

| 專案 | `knowledge/skills/` 裡的 domain skill |
|---|---|
| semorphe | **12**（component-discover / -fuzz / -roundtrip / -encapsulate / build-guardrail / diagnose-in-browser…） |
| VizGPT | 7（commit-feature / visual-diff / browser-measure / concept-sweep / teaching-page…） |
| ArduinoCAD | 2（add-part / over-justify） |
| wewayfinders | 2（deploy-component / probe-production） |
| KnowField | 1（evaluate-and-add-source） |

**5/5 專案兌現，而 knowie 自己記成「未達成」。**

## 為什麼漏掉——不是懶，是結構

judge 只掃 `knowledge/`（這是對的，見 [experience](../experience.md)「why-lane 不掃 what-consistency」）。但 knowie 有**一整批驗證類 roadmap 項，它們的證據天生不在自己的 repo 裡**：

- 程序記憶自習得（domain skill 真的長出來 → 在使用者的專案）
- next 召回率（真實使用中命中 → 在使用者的專案）
- 軟介面硬化（同主題反覆觸發推進一階 → 在使用者的專案）
- FUSE 掛載（adapter 餵進後端 → 在別人的後端）

這是 [協議非平台](../concepts/協議非平台.md) 的**代價面**：knowie 寄生在別人的 repo 裡，所以它的兌現證據天然分散、而它沒有回收管道。結果是**系統性低估自己**——`history/010`（階段二外推驗證，n=2）之後又跑了三個專案，沒有一個回流。

> 這條的形狀跟 [experience](../experience.md)「反覆使用的隱性判準，會以為已固化、其實沒」是對偶：那條是「用熟了以為記了」，這條是「**做到了以為記了**」。兩條都逃過捕捉，因為它們不長得像「新東西」。

## 提案 A：驗證類 roadmap 項要掛「證據指標」

roadmap 項現在只有 `- [ ]` + 驗收文字。給驗證類的項加一行 evidence pointer：

```markdown
- [ ] 在一個真實專案長出至少一個 domain skill
  - 證據：`../semorphe/knowledge/skills/`（相對於 knowie repo 的路徑或 repo 名）
```

judge 掃到 evidence pointer → 若路徑存在且非空，**提出「這項可能已兌現，去確認」**（不自動勾——人定案是不可外包的，延伸原則 5）。

不做的：把外部 repo 的內容抄進來（那是 what，且會漂）。只留指標，符合 [根本原則二](../principles.md)「回溯所需，不是複製 what」。

## 提案 B：`skills/` 有兩類，而目前只認一類

審計撞到：`over-justify`（判斷過度抽象）**同時存在於 ArduinoCAD 和 semorphe**，38 行 vs 39 行，md5 不同——手動複製後各自漂移。

看整份清單就清楚了：

- **domain skill**（綁 endeavor）：`add-part`、`component-*`、`evaluate-and-add-source`、`teaching-page`
- **endeavor-independent skill**（不屬於任何專案）：`over-justify`、`commit-feature`、`visual-diff`、`diagnose-in-browser`、`build-guardrail`、`browser-measure`

第二類目前**只能靠 copy-paste 傳播**，而 copy-paste 的結局 [experience](../experience.md) 早就寫了：「重複的知識會獨立漂移——解法是單一 source + 委派，不是靠對齊警覺」。over-justify 已經是這條的第一個跨專案實例。

最小可行解（不是「跨專案知識庫」那麼大的東西）：

1. `skills/` 的 `SKILL.md` frontmatter 加一個可選欄位標來源，例如 `origin: <repo>@<commit>`（沒有就是本專案原生）。
2. judge §5 掃到有 origin 的 skill → 報「上游可能變了，去對一下」。
3. 不做同步機制、不做 registry——那會走回平台化（[experience](../experience.md)「在場的 AI 自己做，CLI 只給 AI 不在場的自舉」）。

這也讓 [能否跨領域-endeavor為單位](2026-06-11-能否跨領域-endeavor為單位.md) 的「跨專案層」從抽象問題變成一個有具體實例的小提案：**不是知識跨專案，是「不綁 endeavor 的那類 skill」跨專案**，範圍小得多。

## 提案 C：`.agents/skills/` 承諾了但沒實作（這條是 what-lane，記在這裡只為留脈絡）

`skills/knowie-capture/SKILL.md` 第 39 行明寫要投影到「`.claude/skills/`, the cross-tool `.agents/skills/`」，judge §5 也說要 re-ensure。實測：**五個專案全部沒有 `.agents/skills/` 目錄**。

而其中四個專案的 `.knowie.json` 註冊的 tools 是 `["agents-md", "speckit"]`——**不是 claude-code**。握手照 AGENTS.md 走，skill 卻只投影到 `.claude/`。所以那條「真實 Codex/Gemini 讀到並用到 domain skill」不只是未驗，是**結構上不可能**。

另外 VizGPT 的 symlink 是絕對路徑（`/Users/timcsy/Documents/Projects/VizGPT/knowledge/skills/...`），其他四個是相對路徑。絕對路徑換 checkout 位置就全斷。

→ 這兩條是 code/skill 的 bug，**不該進 knowledge/**（why-lane 不掃 what-consistency）。留在這裡只是脈絡；修法進 roadmap。

## 出口

三個提案都是 design 型 → 成熟後出口是 **vision roadmap**（人定案），不是直接固化。
本檔留到那些 roadmap 項完成才退場。
