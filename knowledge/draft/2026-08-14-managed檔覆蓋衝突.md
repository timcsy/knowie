# managed 檔的覆蓋衝突：base 是慣例的產地，而 update 會把它洗掉

> 2026-08-14 討論。draft，problem 型。
> 怎麼冒出來的：使用者問「knowie 每次更版之後都要先更新自己嗎？」。答案本身很短（改過 `templates/`／`skills/` 才需要，當煙霧測試），但拆問題時撞到一個更大的：**`update` 只修下游，而這次真正漂掉的是上游**。

## 事實

0.6.9 刻意把 subdir README 從「never overwrite」改成 **`overwrite: true`**，理由很硬：README 是檔名/格式約定的唯一來源，裝不到或不更新，下游代謝就會猜錯格式（battle 的 `history/` 被套成日期前綴就是這樣來的）。**managed files 必須可刷新**，這條沒有問題。

但 2026-08-14 整理 knowie 自己的 base 時，diff 出另一個方向：

| 檔 | 方向 |
|---|---|
| `draft/README.md` | **本地比模板豐富**——「同一主題再聊 → 開新檔（新日期），多個快照＝該固化的信號」這條慣例在 knowie 自己的 base 長了約兩個月，模板從沒拿到 |
| `history/`、`episodes/README.md` | 模板比本地新（0.7.2 + 0.7.3） |
| `concepts/README.md` | 本地多一張索引表，而且已經漂了（8 個概念只列 7 個） |

**如果那次沒有先 diff 就跑 `update`，`draft/README` 那條慣例會被無聲洗掉。**

## 問題

**base 是慣例的產地**——真實使用中長出來的約定，第一次出現一定是在某個 base 的 README 裡，不是在 `templates/`。而 `update` 對這個方向只有一個行為：覆蓋。

目前**沒有任何機制**處理這個衝突：不警告、不合併、不備份、不 diff。使用者改過的 managed 檔，下次 `npx knowie update` 就沒了，而且**沒有任何訊號**——這正是 [概念級的死引用](../concepts/why沒有oracle.md) 那一族：不會報錯，只會靜靜地不見。

**對使用者一樣成立。** 這不是 knowie dogfood 的特殊處境——五個真實專案也會在自己的 README 裡加約定（semorphe 就自己發明了 `draft/retired/`）。knowie 只是剛好是第一個被 diff 到的實例。

## 張力（兩邊都是對的）

- **必須可刷新**：約定住在一個會被繞過的地方，等於沒有來源（0.6.9 的教訓）。
- **使用者會編輯它們**：而且他們編輯的內容，往往正是下一版模板該有的東西。

所以解法不能是「不覆蓋」，也不能是「照樣覆蓋」。

## 候選解

**(a) marker 圈出 knowie 管的區塊** — 跟 handshake 已經在用的招數同一個（`<!-- Knowie: ... -->` / `<!-- /Knowie -->`）。覆蓋只動 marker 內，marker 外是使用者的，永遠保留。
→ 最像 knowie 既有的語彙，機制已經存在、只是沒用在 README 上。問題：README 目前整份都是 knowie 的內容，要重新界定「哪一段是可覆蓋的」。

**(b) 覆蓋前偵測「使用者改過」** — 在 `.knowie.json` 存上次安裝的模板 hash；覆蓋前比對本地檔，不一致＝使用者改過 → 警告 + 備份成 `.orig`（dpkg conffile / Homebrew 的做法）。
→ 不必改 README 結構，但只給得起「警告」，不會自動合併；而且多一份 hash 狀態要維護。

**(c) 只報不覆蓋** — 已被 0.6.9 否決（不裝就等於沒有來源）。留墓碑，別重想。

**(d) 對 knowie 自己：CI 雙向比對** — ✅ 2026-08-14 已建（`.github/workflows/check.yml`）：本地與模板不同就紅，訊息明講兩個方向（落後 → 跑 update；領先 → 先回流到模板，否則 update 會洗掉它）。
→ 只覆蓋 knowie 自己這一個 repo，**對使用者的 base 沒有幫助**。這是這條 draft 剩下的全部價值所在。

## 為什麼這條可能比看起來大

它是 [協議非平台](../concepts/協議非平台.md) 的一個具體代價：knowie 不擁有 runtime，只能靠「檔案 + 覆蓋」傳遞約定，而檔案同時是使用者的編輯面。**任何寄生在別人 repo 裡的協議都會撞到這個**（`.gitignore`、`.editorconfig`、各種 rules 檔都有同樣的問題，而它們大多也沒解）。

也和 [驗證證據在外部repo](2026-08-14-驗證證據在外部repo.md) 對稱：那條是「使用者 base 裡的**證據**回不來」，這條是「使用者 base 裡的**慣例**回不來，還會被洗掉」。兩條共同的根是——**knowie 的邊界之外有它需要的東西，而它沒有回收管道**。這個共同根可能才是母概念，兩條都只是它的投影。

## 出口

- problem 型 → 出口是找到答案（→ 變成 design 或 experience）。
- 成熟後：候選解 (a)/(b) 擇一 → 提 vision roadmap（帶驗收 + 雙向連回本檔）。
- 「knowie 的邊界之外」若真是母概念 → 人認定後開 `concepts/` 檔（母概念認定是人的事）。
